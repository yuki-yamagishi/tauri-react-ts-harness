# ADR-0001: クリーンアーキテクチャと純粋ドメインロジックの採用

- **ステータス**: **Accepted**
- **決定日**: 2026-08-30
- **決定者**: 開発チーム

---

## 1. 背景と課題 (Context & Problem Statement)
AI コーディングエージェントとの協調開発において、最も頻発する品質リスクは「UIの軽微な修正時に背後のビジネスロジックや計算式を誤って破壊してしまう（サイレントデグレ）」ことである。
また、UI コンポーネント内に複雑な計算ロジックが混在すると、単体テストの実行に DOM レンダリングが必要となり、テスト実行速度が低下して AI の自己検証ループが滞る課題があった。

## 2. 検討された選択肢 (Considered Options)
1. **選択肢 1: 従来型 React コンポーネント駆動（ロジックを Hooks/コンポーネント内に同居）**
2. **選択肢 2: ドメイン駆動・機能駆動クリーンアーキテクチャ（`src/core/` に純粋ロジックを完全分離）**

## 3. 決定内容と理由 (Decision Outcome & Rationale)
- **採用**: **選択肢 2（クリーンアーキテクチャ）**
- **理由**:
  1. `src/core/` 内のコードは React や DOM、ブラウザ API への依存を一切持たない純粋関数・純粋 TypeScript で構成されるため、Vitest によりミリ秒単位で 100% 単体テストが可能。
  2. UI のデザイン変更やフレームワークの移行が発生しても、コアビジネスロジックが一切影響を受けない高い耐障害性を担保できる。
  3. AI エージェントに対して「UI を触るときは `src/core/` に手を入れない」という明確な境界線を指示できる。

## 4. トレードオフと影響 (Consequences & Trade-offs)
### メリット
- テスト実行が極めて高速かつ堅牢。
- コンテキストドリフトによるロジック破壊を単体テストで 100% 防止可能。
### 制約
- 簡単な状態変更であっても、コアロジック層と UI 層の分離を意識したディレクトリ設計が必要となる。
